
# Тестовое задание в LEKTON
Система управления книгами в библиотеке

## Инструкция по запуску
Находясь в корне проекта, написать:<br />
Windows CMD:
```cmd
./gradlew.bat app:run --console=plain --quiet
```
Windows PowerShell/Linux/macOS:
```bash
./gradlew app:run --console=plain --quiet
```

## Тестирование
Находясь в корне проекта, написать:<br />
Windows CMD:
```cmd
./gradlew.bat app:test
```
Windows PowerShell/Linux/macOS:
```bash
./gradlew app:test
```

## Общее описание решения
Для улучшения архитектуры решения, для реализации команд был
использован паттерн объектно-ориентированного программирования
"Команда", который создается в классе `CommandFactory`.<br />

Все данные хранятся внутри класса LibraryRepository. Помимо
базового функционала (Create, Read, Delete) кэширует статистику,
грамотно ее инвалидирует (инвалидация происходит в случае,
если команды Add или Remove непосредственно затронули
статистику).<br />

Для оптимизации поиска, каждая книга (класс `Book`) рассчитывает для
себя `searchKey` - ключ формата `"title_lowercase author_lowercase"`,
чтобы было легко искать с помощью `String.contains()`.<br />

Взаимодействие с пользователем происходит через класс
`LibraryIOHandler`, который принимает для себя `InputBuffer` и
`OutputBuffer`. Использует `BufferedReader` и `BufferedWriter`,
т. к. они эффективнее, чем `Scanner` и `System.out.print()`.<br />

Для реализации ошибок, были использованы исключения. Они наследуют
абстрактный класс `LibraryCheckedException`, чтобы
их было удобно отлавливать (достаточно поймать только базовый
класс). Исключения проверяемые, т. к. являются исключениями
бизнес-логики и после них можно безопасно восстановиться.
